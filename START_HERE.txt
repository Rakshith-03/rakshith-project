BATTERY PLATFORM - START HERE
==============================

1. WHAT THIS PROJECT IS
-----------------------
A virtual battery lab and software BMS (battery management system) development platform.
It is NOT a certified battery controller. Simulated data is always labelled as simulated.

It does four things:
  - Models battery cells (Li-ion NMC fully validated; Ni-Cd provisional) calibrated on real CALCE lab data.
  - Runs virtual experiments: pulse, ripple, step and drive-cycle loads, with safety limits and moderation.
  - Software BMS: state of charge (coulomb counting + EKF), state of health, resistance, power limits,
    charging strategies (CC-CV, adaptive), pack balancing, ML models with an approval rule.
  - Automation: 11 n8n workflows trigger jobs (campaigns, experiments, diagnostics, ML training,
    reports, error recovery) by calling the backend over HTTP.

How the parts fit together:

  Real data (DATA/RAW_REFERENCE)  -->  MATLAB / Simulink (calibration + validation, MATLAB/ folder)
                                            |  approved parameters -> DATA/MODELS/*.json
                                            v
  Python backend (backend/bp, FastAPI)  -- same model as MATLAB, checked by tests to within 0.02 mV
     dashboard at http://127.0.0.1:8000/ , 44 API routes, SQLite database in DATA/DATABASE
                                            ^
                                            |  HTTP only
  n8n (Docker, 11 workflows in n8n/workflows)  -- orchestration only, no physics, no passwords stored

Status:
  Li-ion INR18650-20R (NMC) model ... VALIDATED on unseen drive cycles (RMSE 12-15 mV), weak below 10% SOC
  Li-ion NCA / LFP .................. NOT SUPPORTED (no data to calibrate)
  Ni-Cd ............................. PROVISIONAL - NOT VALIDATED (only data file is simulated)
  Thermal model ..................... PROVISIONAL (no temperature measurements)
  Simulink model .................... matches MATLAB (<= 0.014 mV)
  Python engine ..................... matches MATLAB (<= 0.02 mV)
  n8n ............................... 11 workflows, live test 15/15 PASS on n8n 2.42.6


2. FOLDERS
----------

3. INSTALL (Windows)
--------------------
  - Python 3.12 or newer (tested on 3.14). python.org - tick "Add Python to PATH" while installing.
  - Docker Desktop (for n8n). docker.com/products/docker-desktop
  - Optional: MATLAB (MATLAB Online is fine) - only for the MATLAB/Simulink side.

Then open PowerShell in this folder and install the Python libraries:

  python -m pip install --user fastapi uvicorn scikit-learn httpx pytest numpy pandas scipy openpyxl matplotlib


4. RUN IT
---------
Step A - test and start the backend (leave this window open):

  cd backend
  python -m pytest -q
  python -m uvicorn bp.api:app --host 0.0.0.0 --port 8000

  All tests should pass. Dashboard: http://127.0.0.1:8000/

Step B - start n8n (new PowerShell window, Docker Desktop running):

  docker run -d --name n8n --restart unless-stopped -p 5678:5678 -v n8n_data:/home/node/.n8n -e BP_API_URL=http://host.docker.internal:8000 -e N8N_BLOCK_ENV_ACCESS_IN_NODE=false docker.n8n.io/n8nio/n8n:2.42.6

  Open http://localhost:5678 and create your own n8n owner account.

Step C - import and activate the 11 workflows (run from this folder):

  docker cp n8n/workflows n8n:/tmp/bp
  docker exec n8n n8n import:workflow --separate --input=/tmp/bp
  docker exec n8n n8n list:workflow | ForEach-Object { docker exec n8n n8n publish:workflow --id=($_ -split '\|')[0] }
  docker restart n8n

  (The publish line assumes n8n has only these 11 workflows, i.e. a fresh install.)

Step D - live test of everything together (backend must be running):

  python n8n/run_webhooks.py

  Expected: 15/15 PASS.

Changing workflows later: edit n8n/make_workflows.py, run it, then push updates with an n8n API key
(n8n Settings -> n8n API):   $env:N8N_API_KEY="<key>"; python n8n/push_workflows.py
Do NOT re-import - that creates duplicates.

6. COMMON PROBLEMS
------------------
  "python not found"         reinstall Python with "Add Python to PATH" ticked, reopen PowerShell.
  docker command fails       start Docker Desktop and wait until it says "running".
  workflows return 500       the backend is not running, or was started without --host 0.0.0.0.
  port 8000/5678 in use      close the other program using it, or restart the PC.
