# n8n workflows

n8n only orchestrates: each workflow is `Webhook -> Prepare (idempotency key) -> backend HTTP call(s) (3 tries, 5 s apart)
-> POST /api/n8n/executions -> respond`. Any backend failure takes the error output -> `POST /api/errors` -> respond 500.
No physics and no control loop run in n8n. Workflows store no credentials; the backend URL comes from `$env.BP_API_URL`.
The JSONs are generated by `python n8n/make_workflows.py` (do not hand-edit `n8n/workflows/*.json`).

| # | Workflow | Webhook path (POST) | Backend calls |
|---|---|---|---|
| 01 | Campaign initialization | `campaign-initialization` | `/api/campaigns` |
| 02 | Automated experiment execution | `experiment-execution` | `/api/experiments` -> `/characterize` -> `/diagnostics` |
| 03 | Constraint moderation events | `constraint-moderation-events` | `GET /api/experiments/{id}` -> `/api/moderate` |
| 04 | Dataset discovery and import | `dataset-discovery` | `/api/datasets/sources` -> `/fetch` (missing known files) -> `/clean` |
| 05 | Data cleaning and approval | `data-cleaning` | `/api/datasets/{id}/clean` |
| 06 | Automatic characterization | `characterization` | `/api/experiments/{id}/characterize` -> `GET /api/experiments/{id}` |
| 07 | Automatic BMS diagnostics | `bms-diagnostics` | `/api/experiments/{id}/diagnostics` |
| 08 | Automatic ML training | `ml-training` | `/api/datasets` -> `/api/ml/train` |
| 09 | Adaptive charging optimization | `adaptive-charging` | `/api/charging/optimize` |
| 10 | Report generation | `report-generation` | `/api/experiments/{id}/report` -> `/api/reports/technical` |
| 11 | Error recovery | `error-recovery` | `GET /api/experiments/{id}` -> re-run via `/api/experiments` |

## Setup (Docker container `n8n`, n8n 2.42.6, port 5678; done on 2026-11-12)
1. Start the backend reachable from Docker: `cd backend; python -m uvicorn bp.api:app --host 0.0.0.0 --port 8000`.
2. The container needs the backend URL and permission to read it (n8n 2.x blocks `$env` in nodes by default).
   It was recreated with the same `n8n_data` volume (existing workflows and credentials kept):
   ```
   docker rm -f n8n
   docker run -d --name n8n --restart unless-stopped -p 5678:5678 -v n8n_data:/home/node/.n8n ^
     -e BP_API_URL=http://host.docker.internal:8000 -e N8N_BLOCK_ENV_ACCESS_IN_NODE=false docker.n8n.io/n8nio/n8n
   ```
3. First import: `docker cp n8n/workflows n8n:/tmp/bp`, `docker exec n8n n8n import:workflow --separate --input=/tmp/bp`,
   `docker exec n8n n8n publish:workflow --id=<id>` for each, then `docker restart n8n`.
   After regenerating, update the existing workflows instead of re-importing (that would duplicate them):
   `set N8N_API_KEY=<key from n8n Settings -> n8n API>` then `python n8n/push_workflows.py`.
4. Live test: `python n8n/run_webhooks.py` (POSTs to `http://localhost:5678/webhook/<path>`).
   Every run appears in `GET /api/n8n/executions`, failures also as `diagnostic_events` rows (`POST /api/errors`).

Bugs the live run found (fixed in `n8n/make_workflows.py`, regression check added to the static test):
- 03 and 09: the JSON bodies contained `}}` inside the expression (`{... pulse_A: 2}})`, `|| {}})`); n8n ends an expression at the

- 04 and 11: when the IF node took the false branch, `Respond` referenced a step that had not run. It now responds with the
  output of the last step that did run.
